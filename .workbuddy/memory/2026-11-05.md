# 2026-11-05

## 第八轮：用户给了 Google Street View APK，要求「直接移植全景拍摄部分」

`ggjj_923827.apk`（44MB，`com.google.android.street`），已加入 `.gitignore` 不入库，
只做静态分析（解包 + 字符串提取），从未执行其中任何二进制。

### 结论：不能直接搬（有铁证）
- `liblightcycle.so` (3.46MB) = ELF64/AArch64，头 `7f454c46`、machine `0xB7`，
  依赖 `libEGL.so` / `libGLESv2.so` / `libandroid.so` / `libjnigraphics.so`，
  导出 `Java_com_google_android_apps_lightcycle_panorama_*` JNI。
- `classes*.dex` = Dalvik 字节码（`dex\n035\0`）。
- `libphotosphere_utils.so` = ELF + Adobe XMP Toolkit 5.5.0。
- Google 从未发布 LightCycle 的 iOS 版，也没开源；so 里 44 个 `.cc` 路径只是调试符号。

### 从符号还原出的引擎结构（很有价值，以后别再自己瞎设计）
```
capture    target_generator / target_manager / gyro_calibrator / fov_calibrator
alignment  spherical_pairwise_match / patch_pairwise_matcher / line_align
optical_flow camera_rotation_model / flow_constraints / global_flow_solver
rendering  seam_finder_graphcut / seam_selection / image_masker / blender
session    metadata_utils / photosphere_parameters
```
**关键发现**：Google 的 rendering 层不做重叠帧加权混合，而是**逐像素选一帧（Graph Cut
最优接缝）**，多频段金字塔只用来抹平接缝两侧的曝光差。接缝代价含
`LaplacianCbCrDiffComputer` / `ExposureUnaryCostComputer`（见 seam_finder_utils.cc）。

### 实际移植的三项（平台无关，已落地）
1. `Stitch/PhotoSphereMetadata.swift` — GPano XMP APP1 注入。字段与
   `geo_photo_service.PanoramaParameters` 逐个核对（FullPano*/CroppedArea*/Pose*/
   InitialView*），命名空间 `http://ns.google.com/photos/1.0/panorama/`。
   补上了 README 里挂了很久的「无 GPano 元数据」缺口。
   `Tools/verify_xmp.py` 验证：marker 链完整、14/14 字段、JPEG 仍可解码。
2. `OrientationProbe` 焦距标定从 7 档粗选 → 粗扫 + 三点抛物线插值精化
   （对应 fov_calibrator.cc 的 Ceres 连续优化）。
3. `CaptureModel.isMovingTooFast`（>70°/s 低通）— 对应
   `LightCycleNative_MovingTooFast` / `PhotoSkippedTooFast`，跳过运动模糊帧。

### 试过但**否定**的一项（重要，别重复踩）
把高频层改成「每像素只取一帧」的 Voronoi 接缝：
- 单层看竖线更锐利，但套上 `composeBands` 后接缝跳变处出现**白色亮斑/断裂**
  （narrow 与 narrowLow 的取值在不同分辨率下偶发不一致，两频段相减放大尖峰）。
- 权重锐化折中 wt^p（p=2/4/8/16/32）指标单调变差：
  PSNR 17.58→17.06、P99 误差 174→180、高频 0.0474→0.0541（真值 0.0448）。
→ **已完整回滚** StitchService 的 shader 改动，保留窄羽化两频段混合。
结论：要移植这条链路必须实现 max-flow + 接缝代价，不是改一行 shader。
完整数据在 `Tools/verify_seam.py`（docstring 里写了结论）。

### 工具坑（第一次遇到，务必记住）
用 Python `open(p,'w')` 在 Windows 上会把 `\n` 写成 `\r\n`。
本仓库行尾是**混合**的：README.md / CaptureModel.swift 原本 CRLF，
StitchService.swift / .gitignore 原本 LF。Python 重写后会造成整文件 diff
（StitchService 一度显示 1442 行变化）。
→ 改文件优先用 Edit 工具；必须用 Python 时，写完检查 `b.count(b'\r\n')`
  并与 `git show HEAD:<file>` 的基准对齐，必要时用二进制写回。
