## 全景720（iPhone 球面全景相机）— 从零构建并出包

工作目录：`D:/ai produe/720`，仓库：https://github.com/gfhghj312-cyber/pano720-ios （public，免费 Actions 额度）

### 技术决策（重要，后续改动要遵守）
- **纯姿态拼接，不用 OpenCV/特征点**：每帧记录 CoreMotion `attitude`（`.xArbitraryZVertical`，Z 轴垂直），
  等距圆柱图逐像素求世界射线 → `c = Rᵀ·w` → 针孔投影 → 边缘羽化 + cos³ 权重混合 + 亮度增益。
  Metal compute shader 以字符串运行时编译（`device.makeLibrary(source:)`），避免 .metal 文件与工程配置。
- **采集用 AVCaptureVideoDataOutput 而非 PhotoOutput**：缓冲区朝向确定（`videoRotationAngle = 90`，
  竖屏锁定），无 EXIF 歧义；镜头内参 `focal = (longEdge/2)/tan(hFOV/2)`，`tanHalf` 是比例所以缩放不变。
- **格式选择**：优先 4:3 且 longEdge ≤ 2400（12MP 视频流会掉帧），2.5s 无出图自动降档到 ≤2000。
- 纹理用 `texture2d_array` 单次绑定（避开 31 个纹理参数上限），源图按张数动态降采样，显存约 140MB。
- 工程用 XcodeGen（`project.yml`），`.xcodeproj` 已 gitignore，CI 里生成。

## 第二轮：拼接全糊 + 空洞 的根因修复（2026-11-01 深夜）

### 根因（两个都是硬 bug）
1. **旋转矩阵传反**：`StitchService` 传给 Metal 的是 `R` 的行，着色器算 `c = R·w`；
   正确应为 `Rᵀ`（世界→相机）。准星视图 `AlignmentReticle` 用的是 `rotation.transpose`，
   两处矛盾 —— 准星是对的，拼接是错的。这直接导致每帧落到错误球面位置、37% 空洞。
2. **机位网格经度步长公式低估**：`stepYaw = 2·asin(sin(stepH/2)/cosP)` 在高纬度严重偏小，
   环与环之间必然留缝。

### 修复要点
- `simd_float3x3.worldToCameraRows4`（传列 = Rᵀ 的行）；着色器注释写明相机沿 -Z。
- `CMAttitude` 旋转方向**运行时用重力判定**（参考系重力恒为 (0,0,-1)，
  与 `deviceMotion.gravity` 比两种解释的误差），不再依赖文档猜测；判定结果统一成「相机→世界」。
  ⚠️ Apple WWDC 与 SO 上的说法互相矛盾，别凭记忆写死方向。
- 机位网格改为**贪心球面覆盖**：5200 个 Fibonacci 采样点，视场矩形（按 overlap 收缩）精确判定覆盖，
  每次在「离所有已有机位最远的未覆盖点」放新机位。极点 (|z|>0.93) 改用旋转不变的圆判定
  （举手机对天顶时滚转角不确定）。
- 姿态按**视频帧 PTS** 在历史里四元数 slerp 取（补偿视频流 1~2 帧延迟）；时间轴不同源时退回当前姿态。
- 超广角：开 `isGeometricDistortionCorrectionEnabled`，读 `geometricDistortionCorrectedVideoFieldOfView`，
  中央 `crop=0.92` 参与拼接。
- 拼接第二轮：未覆盖像素放宽边界 45% + 钳制采样做边缘外推，杜绝黑块。
- `setBytes` 有 4KB 上限 → 参数表改用 `MTLBuffer`。

### 参数（仿真定标）
`overlap=0.16` → 1× 约 35 张，0.5× 约 14 张；`feather=0.11`(ext.w)。

### 验证方法（重要，可复用）
`Tools/verify_stitch.py`：合成全景 → 按机位 pinhole 反投影出帧 → 用与 MSL 逐字对应的公式拼回 → 比真值。
结论：正确 Rᵀ = 0% 空洞 / PSNR 31.4dB（误差均匀，只有极区 1~2 行拉伸）；
传 R = 37% 空洞 / 7.9dB。±0.7° 姿态抖动下 PSNR 几乎不变。
